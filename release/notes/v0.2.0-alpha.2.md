## Breaking: the recovery key is now 24 words

Recovery keys are written as 24 words of the BIP39 English list instead of 64 hex digits (ADR-015). The old hex
format is no longer accepted anywhere: the console gate, disaster recovery and the configuration backup ask for the
24 words. **An appliance installed from 0.1.0-alpha has a hex recovery key: re-install it from this release** and
write down the new key at first boot. There is no conversion.

## Highlights

(The tags v0.2.0-alpha and v0.2.0-alpha.1 were never released: their image builds failed on the build host.
0.2.0-alpha.2 is the first release of this line.)

- **Offline updates:** appliances without internet access update from `nexusbackup-<version>-update.tar`, uploaded
  in Settings, Updates; the appliance checks the image signature against its pinned release keys before anything
  is installed (manual chapter 13).
- **Edge proxy ISO:** `nexusbackup-edge-<version>-x86_64.iso` for roaming laptops (docs/edge.md). Built for the
  first time; not yet tested as a VM.
- **Time servers:** configurable in Settings, Time (manual chapter 2), with the state of every source. NTS only by
  default; plain NTP servers (isolated networks with an internal time server) only as an explicit opt-in. Changes
  need approval when approvals are enabled.
- **Smaller image:** only the packages the appliance runs (no dnf, sudo, sssd, Samba client libraries, Bluetooth,
  GPU/Wi-Fi/audio firmware, translations, man pages); every package updated at build time. The rechunked image is
  1.26 GB (1.40 GB before) and the offline update bundle about 610 MB.
- **Security:** zip 9 (RUSTSEC-2026-0367/0368/0369); chacha20poly1305 0.11, rustls-webpki 0.103.16, tantivy 0.27
  (lru 0.18.5), totp-rs 6; the Linux desktop agent talks D-Bus through zbus 6 (no more zbus 5,
  RUSTSEC-2026-0370..0372); flagged snapshots: bare-metal and P2V restores refused, downloads for administrators
  only; CVE gate with reviewed exceptions (docs/security-review.md).
- **Post-quantum TLS:** the web UI and API, replication, agents and the edge proxy prefer the hybrid key exchange
  X25519MLKEM768 (browsers and OpenSSL 3.5 offer it); older peers use X25519 as before.
- **Hardening (CIS):** kernel and network settings, unused protocols and file systems blocked, no core dumps,
  persistent journal, `/tmp` and `/dev/shm` without exec, hardened (still disabled) sshd configuration; the release
  fails when a CIS rule that passed before no longer passes (docs/cis.md for every rule and the reason where the
  appliance deviates). The file index only fetches keys from the key service, nothing else.
- **Risk signals:** thresholds are a setting (Settings, Security; changes need approval) and an API token used from a
  new network marks its account.
- **More:** file search by owner; content hashes on btrfs (also zlib/zstd compressed), FAT and exFAT volumes; the configuration backup also goes to a
  tenant's second offsite target; live progress for NAS shares, plugin jobs and agent release pushes; from a failing
  disk straight to its array's actions.
- **Fixed:** the diagnostic `time.nts` always warned "no NTS-authenticated time source"; the MySQL point-in-time
  restore showed a tail error instead of the server's log when its temporary server failed.
- **Agents:** packages tested on 14 Linux releases (docs/compatibility.md); connect errors name the likely cause.
- **Appliance VMs:** use VirtIO SCSI single for the disks (manual chapter 2).
